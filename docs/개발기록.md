### [10/04] [저장소 담당] AI 기능을 유료 API 없이 어떻게 만들지 결정
- 사용 AI: Claude Code
- 문제: 기획안의 "AI 기준 추천 / AI 설명 / 다음 결정 추천"을 만들려면 AI API가 필요해 보였지만, 무료 범위·키 노출·발표 당일 300~400명 동시 접속이 걱정됨
- 원인: 서버 없는 정적 사이트에서 AI API를 부르면 키가 화면 코드(JS)에 들어가 누구나 볼 수 있음. 무료 API는 분당 호출 수 제한이 있어 동시 접속 시 오류 발생
- 초안 프롬프트: "AI 기능은 유료 AI API 키를 쓰지 않는 방식으로 만들어줘. data/ JSON 데이터와 규칙(키워드 매칭, 점수 계산, 문장 템플릿)으로 구현해줘."
- 수정 프롬프트: (회사 가이드라인 원문을 붙여넣고) "무료 api 연동하고 연속호출시 지연기능 넣기 하면 가이드라인과 어긋나니?"
- 수정 이유: 처음에는 "서버 호출 금지"로 스스로 정했지만, 회사 가이드라인은 금지가 아니라 "외부 API 호출 최소화"였음. 다른 AI와 답이 달라 원문 기준으로 다시 확인함
- 결과·검증:
  - Before: AI API 사용 전면 금지 (규칙 방식만)
  - After: **규칙 방식을 먼저 완성**하고, 무료 AI는 마지막 단계에 결과 설명 1회에만 덤으로 사용. 키는 Vercel 환경 변수에만 두고, 실패하거나 키가 없으면 규칙 설명으로 자동 대체
  - 검증: 가이드라인 4개 조건(키를 코드에 넣지 않기 / 외부 호출 최소화 / 내려받아 바로 실행 / 300~400명 동시 접속)을 모두 만족하는지 하나씩 대조함. "연속 호출 지연"만으로는 한 사람의 연타만 막고 400명 동시 접속은 못 막는다는 점을 확인해 대체(fallback) 기능을 필수로 정함

### [10/05] [저장소 담당] 설명 문장의 조사(은/는, 이/가)가 선택지 이름에 따라 틀리는 문제 예방

- 초안 프롬프트: "확인했어 다음" (4단계: 기준·키워드·문장 틀·다음 결정 데이터 초안 작성)

- 결과·검증:

  - After: 아이콘 정상 / "이미 있어서 그걸 선택해 두었어요" 안내 / "연봉·처우를 가장 중요하게 보고 있어요 (60%)"
  - 검증: 조사 도구(Pickwise.josa)를 스페인·그리스·날씨·예산·서울·iPhone으로 시험 → 스페인은/그리스는/서울로/예산으로 등 정상. 슬라이더를 60→100→40으로 움직여도 합계 항상 100%, 기준 삭제·추가 후에도 100% 유지, 콘솔 오류 0건

### [10/05] [저장소 담당] 중요도 설정: "합계 100% 고정" → "기준별 0~10점 + 비중 자동 계산" (기획 의도 반영)
- 사용 AI: Claude Code
- 문제: 처음 기획 문구("슬라이더, 합계 100%")대로 만들었더니, 한 기준을 올리면 다른 기준이 저절로 내려가 "예산도 높게, 날씨도 높게"처럼 생각한 대로 맞추기 어려움
- 원인: 중요도의 목적은 **기준끼리의 상대 비교**인데, 사용자가 합계까지 맞추도록 만든 설계가 목적보다 제약이 컸음
- 초안 프롬프트: "3 중요도 설정(슬라이더, 합계 100%)"
- 수정 프롬프트: "중요도 설정시에 합계가 항상 100% 되는게 필수적인건 아니야. 상대적인 중요도 비교용이야" → (Claude 제안 확인 후) "응 바꿔줘"
- 수정 이유: 사용자가 각 기준을 독립적으로 정하고, 비교 결과(비중)는 앱이 계산해 주는 것이 의사결정 도우미의 취지에 맞음
- 결과·검증:
  - Before: 날씨를 올리면 예산·관광 등 나머지가 자동으로 줄어듦 (합계 100% 고정)
  - After: 기준마다 0~10점을 따로 정하고, 옆에 비중(%)을 자동 표시. 예) 예산 10점(31%) · 날씨 8점(24%) …
  - 검증: 날씨를 8→10점으로 바꿔도 다른 기준 점수 변화 없음, 비중만 다시 계산(31%→29%). 모두 0점이면 다음으로 못 넘어가고 안내, "모두 5점으로" 누르면 안내 사라짐. 기준 추가 시 새 기준 5점, 삭제 후 정상
  - 기획안과 달라진 부분이라 PPT에 "내부 피드백으로 바꾼 것"으로 쓸 수 있음

### [10/05] [저장소 담당] 화면 4: 설명글로 별점 자동 제안 — 부정 표현("~지 않다", "없다") 처리
- 사용 AI: Claude Code (내장 브라우저로 입력 시나리오 자동 점검)
- 문제: 설명글 키워드로 별점을 제안할 때 "볼거리가 없어요"의 "없"이 부정어 목록("없")에도 걸려서, 나쁜 표현이 다시 좋은 표현으로 뒤집힐 위험이 있었음 (설계 중 발견)
- 원인: 나쁜 표현 단어("볼거리가 없") 안에 부정어("없")가 그대로 들어 있음
- 초안 프롬프트: "둘다 넣어줘 / 확인했어, 다음" (6-1단계: 정보 입력 + 점수 계산 + 모름 버튼 + 검색해보기)
- 수정 프롬프트: (Claude Code가 규칙을 "찾은 단어를 문장 조각에서 지운 뒤 부정어를 확인"으로 설계)
- 수정 이유: "비싸지 않다"는 뒤집고, "볼거리가 없다"는 뒤집지 않아야 사용자 글의 뜻과 맞음
- 결과·검증 (입력 → 제안 별점):
  - "물가가 비싸지 않고" → 예산 4점 (부정어로 뒤집힘 ✅)
  - "날씨가 안 좋아요" → 날씨 2점 (부정어로 뒤집힘 ✅)
  - "볼거리가 없어요" → 관광·볼거리 2점 (뒤집히지 않음 ✅)
  - "음식이 너무 맛있어요" → 음식 5점 (강조어로 +2 ✅)
  - 예시(그리스) 설명 → 예산 2 · 날씨 4 · 관광 4 · 음식 4 · 이동 "정보 없음" / 이집트 → 예산 4 · 날씨 1 · 관광 4 · 음식 "정보 없음" · 이동 2
  - 직접 고른 별점은 설명을 더 써도 유지됨, 아무 정보 없이 다음 누르면 안내 후 막힘, 콘솔 오류 0건

### [10/05] [저장소 담당] 중요도가 같은 기준이 여러 개인데 하나만 "가장 중요"로 표시
