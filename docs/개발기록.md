### [10/04] [저장소 담당] AI 기능을 유료 API 없이 어떻게 만들지 결정
- 사용 AI: Claude Code
- 문제: 기획안의 "AI 기준 추천 / AI 설명 / 다음 결정 추천"을 만들려면 AI API가 필요해 보였지만, 무료 범위·키 노출·발표 당일 300~400명 동시 접속이 걱정됨
- 원인: 서버 없는 정적 사이트에서 AI API를 부르면 키가 화면 코드(JS)에 들어가 누구나 볼 수 있음. 무료 API는 분당 호출 수 제한이 있어 동시 접속 시 오류 발생
- 초안 프롬프트: "AI 기능은 유료 AI API 키를 쓰지 않는 방식으로 만들어줘. data/ JSON 데이터와 규칙(키워드 매칭, 점수 계산, 문장 템플릿)으로 구현해줘."
- 수정 프롬프트: (회사 가이드라인 원문을 붙여넣고) "무료 api 연동하고 연속호출시 지연기능 넣기 하면 가이드라인과 어긋나니?"
- 수정 이유: 처음에는 "서버 호출 금지"로 스스로 정했지만, 회사 가이드라인은 금지가 아니라 "외부 API 호출 최소화"였음. 다른 AI와 답이 달라 원문 기준으로 다시 확인함
- 결과·검증:
  - Before: AI API 사용 전면 금지 (규칙 방식만)
  - After: **규칙 방식을 먼저 완성**하고, 무료 AI는 마지막 단계에 결과 설명 1회에만 덤으로 사용. 키는 Vercel 환경 변수에만 두고, 실패하거나 키가 없으면 규칙 설명으로 자동 대체
  - 검증: 가이드라인 4개 조건(키를 코드에 넣지 않기 / 외부 호출 최소화 / 내려받아 바로 실행 / 300~400명 동시 접속)을 모두 만족하는지 하나씩 대조함. "연속 호출 지연"만으로는 한 사람의 연타만 막고 400명 동시 접속은 못 막는다는 점을 확인해 대체(fallback) 기능을 필수로 정함

### [10/04] [저장소 담당] 내려받은 코드를 더블클릭하면 데이터가 안 읽히는 문제 예방
- 사용 AI: Claude Code
- 문제: 가이드라인상 심사위원이 코드를 내려받아 바로 실행할 수 있어야 하는데, `index.html`을 더블클릭해서 열면 크롬이 `data/*.json` 읽기를 막음 (코드 작성 전 사전 발견)
- 원인: 브라우저 보안 규칙상 내 컴퓨터 파일로 열린 페이지는 다른 파일을 `fetch`로 불러올 수 없음
- 초안 프롬프트: "앱에 들어가는 고정 데이터는 data/ 폴더의 JSON 파일로 만들어줘."
- 수정 프롬프트: "A로 해줘" (데이터 파일을 `.js`로 만드는 안 선택)
- 수정 이유: 배포 주소뿐 아니라 내려받아 더블클릭하는 경우에도 작동해야 하므로
- 결과·검증:
  - Before: `data/criteria.json` 등을 `fetch`로 읽는 구조
  - After: `data/criteria.js` 등에 `Pickwise.data.criteria = {...}` 형태로 저장하고 `<script>`로 불러옴
  - 검증: 이후 모든 단계에서 ① 더블클릭 ② 배포 주소, 두 가지로 확인하는 규칙을 CLAUDE.md에 추가함

### [10/05] [저장소 담당] 화면 1 뼈대 이전 중 로고 글자 사이 빈칸 + 미리보기 수정 실패
- 사용 AI: Claude Code, Claude Artifact
- 문제: ① Artifact 미리보기 수정 요청 후 화면이 바뀌지 않음 ② index.html로 옮긴 뒤 로고가 "Pick wise"처럼 띄어져 보임
- 원인: ① 이 PC에 Python이 설치되어 있지 않아 자동 수정 스크립트가 실패했는데, 수정 전 파일이 그대로 다시 게시됨 ② 로고 전체에 준 글자 간격(gap)이 "Pick"과 "wise" 사이에도 적용됨
- 초안 프롬프트: "미리보기를 실제 앱에서는 '예시로 체험하기' 버튼으로 넣어줘"
- 수정 프롬프트: (Claude Code가 실패를 확인하고 파일을 직접 수정하는 방식으로 재시도)
- 수정 이유: 도구가 없는 환경에서도 동작하는 방법으로 바꿔야 했음
- 결과·검증:
  - Before: 미리보기 2번째 버전이 1번째와 동일 / 로고 "Pick wise"
  - After: 3번째 버전에서 빈칸 시작 + 예시 버튼 확인 / 로고 "Pickwise"로 붙음
  - 검증: 휴대폰 크기(375px)·PC(1280px) 화면 캡처로 확인. 빈칸 다음 클릭 시 안내 문구, 예시 버튼, 선택지 4개 제한, 중복 선택지 차단, 주제 분류(여행/취업·이직/주거/소비/기타), 다음·뒤로가기·휴대폰 뒤로가기, 주소로 건너뛰기 차단, 6단계 "새 결정 시작하기" 초기화를 자동 점검 → 모두 정상, 콘솔 오류 0건

### [10/05] [저장소 담당] 설명 문장의 조사(은/는, 이/가)가 선택지 이름에 따라 틀리는 문제 예방
- 사용 AI: Claude Code
- 문제: 결과 설명 문장 틀을 "{winner}는 …"처럼 조사를 고정해서 쓰면, 선택지가 "스페인"처럼 받침으로 끝날 때 "스페인는"이 됨 (데이터 작성 중 사전 발견)
- 원인: 한국어 조사는 앞 글자의 받침 유무에 따라 바뀌는데, 문장 틀은 어떤 이름이 들어올지 모름
- 초안 프롬프트: "확인했어 다음" (4단계: 기준·키워드·문장 틀·다음 결정 데이터 초안 작성)
- 수정 프롬프트: (Claude Code가 작성 중 문제를 발견해 문장 틀 형식을 바꿈)
- 수정 이유: 사용자가 어떤 선택지 이름을 입력해도 자연스러운 문장이 나와야 하므로
- 결과·검증:
  - Before: "{winner}는 {c1}과 {c2}에서 앞서고…" → "스페인는 날씨과 …"
  - After: "{winner:은는} {c1:과와} {c2}에서 앞서고…" → 받침에 따라 "스페인은 날씨와 …" / "그리스는 예산과 …"
  - 검증: 데이터 자동 점검으로 조사 표기 5종(은는·이가·을를·과와·으로로) 외 잘못된 표기 0건 확인. 실제 조사 변환은 결과 화면(explain.js) 구현 때 검증 예정
