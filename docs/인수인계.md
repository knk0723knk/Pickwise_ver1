- **8.5단계 조원 개선 (10/06 완료):** 표 7의 8개 개선 항목을 모두 반영 — 점수 단어(말끝 바뀜·자주 쓰는 단어), 분류 단어, 시나리오 없는 주제·일반 자취 고민의 기준(`data/criteria-general.js`), 휴대폰 탭·PC 카드 너비, 결과 점수 카드, 설명 문장, 슬라이더 터치 영역, 다음 결정 추천. 자세한 내용은 `docs/개발기록.md` 10/06 "8.5 개선" 항목
- **남은 일:** 9단계 최종 점검·제출 (마감 **10/8(목) 오전 11:00**). 휴대폰에서 슬라이더를 손가락으로 움직여 보는 확인 포함

## 2. 앱이 동작하는 방식 (꼭 알아야 할 것만)
| 화면 | 하는 일 | 파일 |
|---|---|---|
| 1 결정 입력 | 주제·선택지 입력, 주제 → 분류(주거·소비·여가·자기계발·금융생활·기타), "예시로 체험하기" 9개 | `js/screen1-decision.js`, `data/topics.js` |
| 2 기준 선택 | 주제에 가장 가까운 데이터셋 시나리오의 기준 추천 (없으면 분류 기준) | `js/screen2-criteria.js`, `data/criteria.js` |
| 3 중요도 | 기준별 0~100, 비중(%) 자동 계산 | `js/screen3-weights.js` |
| 4 정보 입력 | 설명글 → 기준 점수(0~100) 자동 제안, 별로 수정, 모름·검색해보기·첨부 | `js/screen4-info.js`, `data/keywords*.js` |
| 5 결과 | 총점 = Σ(점수×중요도)÷Σ중요도, 한 줄 요약, 그래프, 확신도, 민감도 | `js/screen5-result.js`, `js/scoring.js`, `js/explain.js`, `js/sensitivity.js` |
| 6 다음 결정 | 다음 결정 추천, 새 결정, 결정 기록(이 기기에만 저장) | `js/screen6-next.js`, `js/storage.js` |

- **AI 표시 부분은 모두 규칙 기반**이에요(키워드·계산·문장 틀). 외부 서버 호출이 없어서 400명이 동시에 써도 멈추지 않아요.
- **데이터팀 데이터셋이 앱 전체의 기준 데이터**예요. `data/samples.js`, `data/criteria.js`, `data/keywords-dataset.js`는 변환 도구가 만든 파일이라 **직접 고치지 않아요.**

## 3. 처음 작업하는 조원 준비 (한 번만)
1. GitHub 가입 → 저장소 대표에게 받은 **초대 메일에서 수락(Accept invitation)** — 직접 누르기
2. Claude Code 데스크톱 앱 설치, 작업할 빈 폴더 하나 만들기
3. Claude Code에 이렇게 요청:
   > GitHub 저장소 https://github.com/knk0723knk/Pickwise_ver1 를 이 폴더로 가져와줘. 브랜치는 만들지 말고 main에서만 작업해줘. 로그인이 필요하면 단계별로 안내해줘.
4. 가져온 뒤:
   > CLAUDE.md와 docs/인수인계.md를 읽고 지금 상태와 내가 할 일을 쉽게 요약해줘.

## 4. 작업할 때마다
1. 팀 톡방에 **"지금 ○○ 작업 중"** 한 줄 올리기 (같은 파일 동시 수정 방지)
2. Claude Code에: **"GitHub에서 최신 내용 받아와줘."**
3. 담당 파일 수정 → 브라우저로 확인 (index.html 더블클릭 + 배포 주소)
4. Claude Code에: **"지금까지 수정한 내용을 main에 올려줘. 무엇을 바꿨는지 한 줄로 기록해줘."**
5. 막혔던 문제·해결 과정은 `docs/개발기록.md` **맨 아래에 추가** (형식은 CLAUDE.md §7)

## 5. ⚠️ 배포가 반영 안 될 때 (Vercel 무료 플랜 제한)
Vercel 무료(Hobby) 플랜은 **배포 계정 주인이 아닌 사람이 올린 수정**의 자동 배포를 막을 수 있어요.
- 확인: 올리고 3분 뒤에도 배포 주소에 반영이 안 되면 → 저장소 대표에게 알리기

- 유료(Pro) 업그레이드는 하지 않아요 (팀 규칙: 무료 범위만)

## 7. 남은 일 (8.5 → 9단계)
### 8.5 조원 개선 — 조원마다 담당 파일 1개 이상 + 개발기록 1건
| 조원 | 담당 | 개선 예시 (코딩 몰라도 Claude에게 말로 요청 가능) |
|---|---|---|
| 1 | 공통 디자인·뒤로가기 | 휴대폰·PC에서 어색한 여백이나 글자 크기 다듬기 |
| 2 | 화면 1·분류 단어 | `data/topics.js`에 사회초년생 고민 단어 늘리기, 분류가 틀리는 주제 찾아 고치기 |
| 3 | 화면 2·기준 | 기준 카드 설명이 이해하기 쉬운지 점검, 기타 분류 기준 다듬기 |
| 4 | 화면 3·중요도 | 슬라이더 사용성(손가락으로 움직이기 쉬운지) 점검·개선 |
| 5 | 화면 4·점수 단어 | 실제로 써 볼 법한 문장을 넣어 보고, 점수가 이상하게 나오는 표현을 찾아 `tools/convert-samples.js`·`data/keywords.js`에 단어 추가 |
| 6 | 화면 5·점수 계산 | 결과 화면 그래프·카드가 한눈에 이해되는지 점검 |
| 7 | 설명·민감도 | `data/templates.js` 설명 문장을 더 자연스럽게 다듬기 |
| 8 | 화면 6·기록 | 다음 결정 추천·기록 목록 사용성 점검 |
| 데이터팀 | 데이터셋 | ① 기본 선택 4곳이 겹침 경고에 걸림(청년전세임대 지역·국내 여행·예금적금·주말 활동) 확인 ② 주거에 일반 자취방 시나리오 추가 검토 ③ 추정값 37개 실제 값 확인 → 원본 JSON 수정 후 `node tools/convert-samples.js docs/원본데이터/원본.json` |

## 8. 알려진 한계 (PPT "제약·미구현"에 쓸 수 있음)
- 설명글 점수는 단어 규칙 기반이라 문장 뜻을 완전히 이해하지는 못해요 → 별로 직접 고칠 수 있게 함
- 첨부 파일은 이름만 기록하고 내용은 분석하지 않아요
- 결정 기록은 사용 중인 브라우저에만 저장돼요 (다른 기기에서 안 보임)
- 주거 데이터셋 시나리오는 청년전세임대뿐이에요. 주제·선택지에 "전세임대·LH·공공임대" 같은 말이 있을 때만 그 기준을 쓰고, 일반 자취방 고민은 일반 주거 기준(통근 시간·치안·방 크기 등, `data/criteria-general.js`)을 써요 (10/06)
- 일부 수치는 추정값이에요 (화면에 "추정" 표시)
